Chromium loads the unmodified pinned source snapshot over loopback HTTP. `capture.py` writes only into this target project. Fresh browser storage is disposable. No donor repository, website, or saved game is modified.

`ride.png`, `dismount.png`, `front-carrier-street.png`, and `front-carrier-walk.png` are actual donor in-game screenshots. The God Mode and warp developer helpers position the reference character safely; normal Q and arrow controls trigger dismount and walking. `renderer-reference-board.png` is a direct canvas renderer reference board, **not an in-game screenshot**. It exercises the same donor hero-rig and continuous passenger functions for front/back carrier poses and original expressions. These are source baselines, not screenshots of newly added content. `capture-report.json` records exact game/rig audits and screenshot SHA-256 hashes.

`character-assets.sha256` hashes the active source character artwork, relevant prepared cycling outputs, and rendering modules (including the bicycle's vector artwork). Paths are relative to the source/target runtime root. The target's deliberately changed game/build/storage code will differ; artwork remains identical.

## Active artwork trace

- Entry load order starts `assets.js`, then illustrated atlases/world/characters, quests/locomotion/combat, `baby-passenger.js`, `hero-rig.js`, NPC motion/art/life, `illustrated-visits.js`, finally `game.js`. Existing IIFEs expose their narrow `window.Bearly*` interfaces. No framework is involved.
- Riding baby: `game.js:mountedBabyFrame()` chooses `baby_pose_idle/laugh/terror/leanBack/leanForward/point/brace/sick.webp` and their measured rack anchors. Only excited and sick expressions select `v151_baby_pose_excited.png` / `v151_baby_pose_sick.png`. A common scale of 1.08 and fixed rack mount preserve attachment. `v149_mounted_*` are archival alternatives, not the active mounted likeness.
- Carrier baby: `baby-passenger.js` loads those original pose WebPs plus the same two V151 overrides. Its polygon retains the original continuous head, chin, neck, collar and upper shirt while excluding the bicycle chair. `hero-rig.js` removes former painted passenger regions from the carrier sheets, restores clean backing, then draws that continuous original passenger at a common native head scale. Only the lower clothing cut is hidden behind the actual curved pouch lip. The source baby must never be replaced with a detached face or a separately drawn neck.
- Hero carrier sheets: `assets/art/front-carrier-v7.png`, `back-carrier-v11.png`, `carrier-reactions-v11.png`, `matched-legs-v11.png`, `bear-near-contact-v18.png`, `bear-near-support-v18.png`, `bear-far-poses-v18.png`, `bear-idle-lower-v18.png`, and the five `*-background-v11-2.png` backing sheets. `locomotion.js` supplies continuous two-leg phase/sole motion; hero-rig applies it to the authored short legs, complete boots and original jersey/fur.
- Visits: `bike-transfer-v7.png` supplies the six dismount poses; first two are drawn intact, later poses pass through hero-rig's native passenger overlay. `boat-passengers-v8.png` goes through the same overlay and lower pouch composition. `dinghy-v7.png` has rear/bench and foreground gunwale layers around the passengers.
- Riding bear: registry `bear_pose_idle` aliases `bear_pedal_3.webp`; other original `bear_pose_*` and `bear_pedal_0..3.webp` supply jersey/face/anatomy. `illustrated-hero.js:source()` redirects pose/pedal/upper requests to lossless `assets/cache/hero-cycling-v19/*.png`, and `sprite()` recognizes prepared files to avoid applying the material treatment twice. `bear_leg_clean.webp` / `bear_leg_original.webp` retain authored fur-to-boot pieces; game loading redirects only pose/pedal/upper names, so the leg material pass is performed by `sprite()` if needed. Manifest hashes cover both prepared outputs and originals.
- Bicycle: the active blue city bicycle is the preserved **canvas artwork** in `game.js:wheel()`, `frame()`, and `bicycleDrive()`. Its fixed original wheel hubs, tyre radius, rack, child mounting point and overall `ART_SCALE=.48` share a single transform with bear/baby. It is not an external bicycle PNG. `v89_bike_crashed.webp` is used for the bent bike after an actual crash. Both `selectedSheetPose()` and `sheetPoseFor()` return null; `sheet_pose_*` and `bear_sheet_*` are archived references and must not be selected as gameplay replacements merely by filename.
- Portrait: the HUD chooses standardized `v158_hud_{happy,terrified,angry,laughing,crying,knocked,excited,sick}.png` from the visible mounted emotion. V153 and older portrait names remain registered but do not supersede that current HUD path.
- Crash override precedence: `assets.js` registry is installed first; `game.js` explicitly overrides crash sources twice. Final active cels are `baby_crash_{drag,falling,impact,ragdoll}_3.png`, `v125_baby_{flail,roll,skid}_3.png`, `v125_baby_cry_wet` aliases `baby_crash_drag_3.png`, V131 cels use their `_2.png` versions, and airborne crash uses `v149_airtime.webp`. The V163 asset override map has precedence over the base registry during `load()`. Preserve those orders.
- NPC identity dependencies remain in `brawler-art.js` adult/reaction/screen sheets V15, `npc-motion.js` motion/civilian sheets V16 and `assets/cache/actors-v19-manifest.json`/prepared actor outputs. Scene atlas prefers `assets/cache/scene-v19-*.png` with original `assets/art` sheets as fallback. Those prepared caches are part of the standalone game, not a runtime donor dependency.

The hashes establish byte identity; they do not replace visual review. Character anatomy/attachment should be compared against the actual rendered frames and board.
