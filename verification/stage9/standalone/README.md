# Stage 9 standalone package validation

The extracted delivery is tested with fresh local HTTP servers at both `/` and the repository subpath `/BQ-Centrum/`, with independent desktop 1280×720 and Chromium phone-landscape 844×390 emulation contexts. This is not physical iPhone/Safari testing.

The test clicks the original title control and performs real keyboard/touch pedal input. Every existing scene is then loaded using explicitly disclosed production-save-factory fixtures with named entrances, a valid recorded parking anchor and 73 HP. Fixtures isolate file/scene loading and are not a claim that this check replayed the complete native ride/story path; that separate path is recorded under the full-route evidence. The new independent gate/passage/cage PNGs must decode and pass their renderer-ready audit in each relevant scene. Both active HTML entries are checked, along with console/HTTP errors, relative asset requests, native baby continuity, project-specific storage, one pending main animation loop, startup and sampled frame intervals. The 944-file source check runs inside the extracted package without an inspection archive or donor checkout.

From the development workspace, with Python Playwright and system `/usr/bin/chromium` available:

```sh
python3 tools/package-project.py
python3 tests/centrum_standalone.py
```

The executable game itself needs only a local static server; Playwright/Chromium are development test tools. Exact controls/start instructions and implemented scope are in the root README.

`results.json`, `frames.sha256`, package-audit JSON, screenshots and archive SHA sidecar are external certificates generated for the archive being tested. They remain in the workspace/delivery output beside the final artifact and are intentionally not embedded as a stale/self-referential earlier-ZIP certificate. Read TEST_REPORT.md for the compact actual results and limitations. Native full-route/edge evidence and the final art gallery are included in the delivery.

Frame intervals are measurements from a shared headless Linux container, not a guarantee of physical-device performance. Source-authored prepared files under `assets/cache` are required immutable runtime assets, not development/browser caches.
