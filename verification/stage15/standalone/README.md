# Stage15 exact standalone archive validation

After the current documentation/runtime freeze, build and test with:

```sh
python3 tools/package-project.py
python3 tests/centrum_standalone.py
```

The test checks the exact delivered archive SHA and every manifest payload hash, then extracts it into a clean directory and serves it at `/` and `/BQ-Centrum/`. Chromium desktop1280×720 and phone-landscape844×390 touch emulation exercise both active HTML aliases, a native ride start and all five existing scene loads. Production-save-factory fixtures provide named arrivals, valid one-bike parking and73HP; these are delivery tests, not another earned quest route. Source/baby/physics integrity is rechecked inside the extraction with no donor inspection checkout.

Native I or Settings→Bag is tested without permanent food/wallet display, including fresh shop dialogue before bag use. Real walking inputs verify authored up/away and down/toward views, continuous original baby scale and original lower-child source. Scene health/supplies, ownership, bounded worker, one loop, source attribution, relative paths, namespace, console/HTTP/external requests are checked. Its36 projection snapshots (20scene arrivals +16walk samples) assert uniform.75 zoom,150 projected height,200 native/world height, unchanged baby scale and coherent projected screen/jump coordinates. The matrix has28 top-level checks; individual assertions are retained in the full result.

Archive-specific results are **external to the ZIP they validate**: `verification/stage15/standalone/results.json`, `archive-review.json`, `package-audit.json`, PNGs/`frames.sha256`, and `delivery/BQ-Centrum-validated.zip.sha256`. They are not included as a stale/self-referential certificate. This page describes the procedure and locations; passing status belongs to the actual generated result. No physical phone/Safari/thermal test is implied. Only a static HTTP server is required to play the game.
