# Stage 11 standalone package validation

The extracted delivery is tested on clean local servers at `/` and `/BQ-Centrum/`, using desktop 1280×720 and Chromium phone-landscape 844×390 emulation. This is not physical iPhone/Safari testing.

The test starts a fresh ride with native title/pedal controls. Every existing scene then loads through a disclosed production-save-factory fixture: named entrance, valid recorded parking and 73 HP. Desktop **I** and touch **Settings → BAG** open the bag; the food/wallet stay hidden during ordinary play. Five hearts remain available in Centrum. Fresh food-shop discovery dialogue must block bag browsing until its visible Close control is used. Browsing/closing preserves health, supplies, quest state and reward claims. Square receives real left/right/up/down keyboard or touch holds; actor/baby continuity, valid one-bike ownership and worker status are recorded.

Both HTML entries, source/environment assets, console/HTTP errors, relative requests, namespaced storage and one pending main animation loop are checked. The strict 944-file source reconstruction runs inside the extracted package without any donor checkout or inspection archive. Fixtures test delivery/scene loading; they do not claim to replace the earlier earned ride/story route or dedicated Stage 11 movement review.

From the development workspace with Python Playwright and system `/usr/bin/chromium`:

```sh
python3 tools/package-project.py
python3 tests/centrum_standalone.py
```

The game itself needs only a static local server. The exact archive certificate, screenshots, audit JSON and SHA sidecar are external to the ZIP they validate, avoiding stale or self-referential certificates. Actual results belong in TEST_REPORT.md after the run; this page describes the test, not a passing claim. Shared headless timings provide no physical-device/thermal guarantee.
