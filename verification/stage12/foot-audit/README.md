# Stage12 source foot audit — read only

All PNGs here are **source artwork references, not gameplay screenshots**. They were drawn from the existing source PNG onto a labelled browser canvas; no artwork files or runtime files were edited. `reference.html` reproduces the crops. `source-audit.json` records exact source hashes, width calculations and read-only pixel rows.

## Findings

The Stage11 renderer uses two different regions of active `bear-near-contact-v18.png`, not literally the same rectangle twice. The near/foreground source boot is the large shoe at heel710,1110→toe1240,1155. The far/background shoe is the small raised boot at100,820→550,1030. However, it rescales the large front shoe to the small idle shoe width and the small rear shoe to the large idle width: at hero200 the resulting spans are34.54 and42.13 pixels. The far shoe becomes larger than the near one. Both source pitches are also normalised flat. Combined with depth-dependent internal layer swapping, this removes the original clear front/back relationship. Generic unmarked boots do not provide proof of medial/lateral anatomical handedness; pointing both toes right is normal in a right-facing walk and alone is not a defect diagnosis.

The original active front-carrier profile has intended near/far rectangles125×84 and108×78 at soles155,500 and220,491. Its near shoe is larger/lower; far is smaller/higher. The standing far heel is occluded by the near toe, so extracting it as a whole separated animated boot is unsafe. Walking frame2 has a complete rear boot around814..925,389..490, but this parent repair chose the already active contact pair with corrected near/far sizing and fixed internal layer order. The experimental `suggested-source-masks-attempt.png` remains only a source trace, not a finished/accepted animation asset.

The idle lower painting contains a second narrow orange fur column on its right side, behind the central fur that actually connects to the right boot. The published Stage11 far calf strip's right edge1191 includes both. Read-only orange-pixel rows confirm separate central/extra clusters, for example y600:613..882 versus893..980; y720:588..867 versus889..966; y800:656..794 versus844..921. It is visible in the original source image and should be excluded from a one-calf patch.

A source mask right edge interpolated through the following y,x points keeps the main central calf while excluding the extra column:560,890;580,881;600,887;620,887;640,888;660,892;680,888;700,885;720,878;740,871;760,861;780,840;800,819. These are source-space boundaries between the measured orange clusters, not invented replacement fur. Actual gameplay still needs to verify the parent repair at normal size; this audit does not certify it playable or anatomically correct.
